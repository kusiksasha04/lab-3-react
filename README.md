# Лабораторна робота — React

Односторінковий застосунок (SPA) **«Список завдань» (Todo app)** на React.
Завдання завантажуються з API. Їх можна додавати, редагувати, видаляти та відмічати як виконані.

## Можливості

- **Завантаження завдань з API** під час відкриття сторінки (GET-запит через axios)
- **Додавання** нового завдання (POST)
- **Редагування** назви завдання (PATCH)
- **Трекінг виконання**: чекбокс «виконано», лічильник «Виконано: X з Y» і смужка прогресу (PATCH)
- **Видалення** завдання (DELETE)
- Повідомлення «Завантаження...», поки дані ще не прийшли, і текст помилки, якщо сервер недоступний
- Перевірка, що не можна додати порожнє завдання

## Технології

- [React 19](https://react.dev) — функціональні компоненти та хуки `useState`, `useEffect`
- [Vite](https://vite.dev) — інструмент для створення, запуску та збирання проєкту
- [axios](https://axios-http.com) — HTTP-запити
- [JSONPlaceholder](https://jsonplaceholder.typicode.com) — безкоштовний тестовий API

> **Чому Vite, а не create-react-app (як у методичці)?**
> Розробники React офіційно визнали create-react-app застарілим (deprecated) і радять Vite.
> Він робить те саме: створює проєкт, запускає сервер розробки з hot reload і збирає застосунок.
> Відмінності для нас мінімальні: файли компонентів мають розширення `.jsx`, а зібраний застосунок лежить у папці `dist` замість `build`.

## Запуск

Потрібен встановлений [Node.js](https://nodejs.org) (версія 20 або новіша).

```bash
npm install     # встановити залежності (один раз)
npm start       # запустити сервер розробки
```

Після запуску відкрийте в браузері адресу, яку покаже термінал (зазвичай http://localhost:5173).
Щоб зупинити сервер, натисніть `Ctrl + C`.

Інші команди:

```bash
npm run build     # зібрати готовий застосунок у папку dist
npm run preview   # переглянути зібрану версію
```

        ├── TodoList.jsx    список завдань

## Як це працює

Дерево компонентів:

```
App                     ← зберігає tasks у state, має функції addTask / editTask / toggleTask / removeTask
├── UpdateList          ← отримує onAddTask через props
└── TodoList            ← отримує tasks, onToggle, onEdit, onDelete через props
    └── TodoItem (×N)   ← отримує одне task і ті самі функції
```

1. **Дані зберігаються в одному місці — у state компонента `App`** (`useState`).
2. `App` передає дані вниз дочірнім компонентам через **props**.
3. Дочірні компоненти самі дані не змінюють. Вони викликають **функції, отримані через props**
   (наприклад, `onDelete(task.id)`), а `App` оновлює state.
4. Після зміни state React автоматично перемальовує інтерфейс.
5. Кожна функція в `App` спочатку оновлює список на екрані, а потім відправляє запит на сервер через `api.js`.

Приклад: що відбувається після натискання «Видалити»

```
TodoItem: onDelete(5)  →  App: removeTask(5)
                            ├── updateTasks(...)  → завдання зникає зі списку
                            └── api.deleteTask(5) → DELETE /todos/5 на сервер
```

### Про API

JSONPlaceholder — це тестовий («фейковий») сервер. Він приймає всі запити й відповідає так, ніби все збережено,
але **насправді нічого не зберігає**. Тому після перезавантаження сторінки знову з'являються ті самі 5 завдань.
Назви завдань там латиною, бо це стандартний текст-заглушка (lorem ipsum).

Ще два нюанси:
- Під час додавання завдання `id` генерується самостійно (`Date.now()`), бо JSONPlaceholder завжди повертає однаковий `id = 201`.
- Для редагування використовується **PATCH** замість PUT. Обидва методи оновлюють запис, але PATCH змінює лише передані поля
  (наприклад, тільки `completed`). Крім того, JSONPlaceholder повертає помилку 404 на PUT для нових завдань, яких немає на сервері, а PATCH працює для будь-яких.

## Відповідність критеріям оцінювання

| Критерій | Де реалізовано |
|---|---|
| Функціональні компоненти | `App`, `UpdateList`, `TodoList`, `TodoItem` — звичайні функції, що повертають JSX |
| State та props | `useState` в `App` (список, завантаження, помилка), в `UpdateList` (текст поля), в `TodoItem` (режим редагування); дані й функції передаються через props |
| Взаємодія з користувачем | форма додавання, кнопки редагування й видалення, чекбокс виконання, обробка подій `onClick`, `onChange`, `onSubmit` |
| Робота з API | `api.js` (axios: GET, POST, PATCH, DELETE), завантаження в `useEffect`, `try/catch`, стан `loading` |

## Можливі запитання на захисті

**Чому список зберігається в `App`, а не в `TodoList`?**
Список потрібен двом компонентам: `UpdateList` (додає завдання) і `TodoList` (показує їх). Тому він зберігається в їхньому спільному батьківському компоненті. Це називається «підняття стану» (lifting state up).

**Навіщо `key={task.id}` у списку?**
За `key` React розрізняє елементи списку й оновлює лише ті, що змінилися. Унікальний `id` кращий за індекс, бо індекси зсуваються після видалення.

**Навіщо `e.preventDefault()` у формі?**
Без нього HTML-форма після відправки перезавантажує сторінку.

**Навіщо `[]` другим аргументом у `useEffect`?**
Порожній масив залежностей означає «виконати один раз після першого показу компонента». Саме тоді й треба завантажити дані.

**Чому в Network видно два GET-запити під час розробки?**
Через `<StrictMode>` у `main.jsx`: у режимі розробки React навмисно запускає ефекти двічі, щоб виявляти помилки. У зібраній версії (`npm run build`) запит один.

**Чим state відрізняється від props?**
State — це власні дані компонента, які він може змінювати (через `set...`). Props компонент отримує від батька і лише читає їх.
